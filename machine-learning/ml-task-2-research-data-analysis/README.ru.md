## 4. Результаты

### Упражнение 1.1 — Структурный обзор

* Shape `(300, 4)`; `department` — категориальный, остальные числовые.
* Пропуски: `salary` 20, `age` 10, `years_exp` 0, `department` 0.
* **9,7 % строк** (29 из 300) имеют хотя бы один пропуск.

### Упражнение 1.2 — Распределения

Гистограмма зарплаты «прилипла» к левому краю из-за пяти точек на ~370k (в 4 раза выше
нормального максимума); boxplot по отделам показывает нормальный ящик около 45k плюс длинный
хвост выбросов в каждом отделе. Медианы по отделам почти одинаковы — зарплата генерировалась
независимо от отдела, значит это внедрённые выбросы, а не реальный эффект.

### Упражнение 1.3 — Выбросы по IQR

Границы для `salary`: **11 845 … 80 803**. Помечено **8 выбросов**: пять внедрённых значений
~370k плюс три обычных хвостовых (11,6k, 81,4k, 92,5k). `age`: 5 помечено, `years_exp`: 1.

### Упражнение 1.4 — Корреляции

Осмысленной корреляции между числовыми колонками нет (`age`/`salary` −0,08,
`age`/`years_exp` −0,05, `salary`/`years_exp` +0,04). Это ожидаемо: синтетические колонки
сгенерированы независимо; единственная связь — внедрённые выбросы, ни с чем не связанные.

### Упражнение 2.1 — Первый проход

* 20 640 строк × 10 колонок; `ocean_proximity` — единственная строковая колонка.
* Пропуски: **`total_bedrooms` 207** (1 %), больше нигде.
* `ocean_proximity`: `<1H OCEAN` 9136, `INLAND` 6551, `NEAR OCEAN` 2658, `NEAR BAY` 2290,
  `ISLAND` 5.

### Упражнение 2.2 — Распределения и асимметрия

* `median_house_value` **ограничена сверху на 500 001** → всплеск на границе.
* `median_income` ограничена ≈15; `housing_median_age` ограничена на 52.
* `total_rooms`, `total_bedrooms`, `population`, `households` сильно смещены вправо →
  помогает логарифм (`np.log1p`).
* `latitude` / `longitude` — географические (двухмодальные), логарифм здесь был бы ошибкой.

### Упражнение 2.3 — География

Классическая карта Калифорнии: плотные скопления Лос-Анджелеса и Bay Area, внутренние районы
дешевле и дальше от побережья. Цвет = стоимость жилья, размер = население.

### Упражнение 2.4 — Корреляция с целевой переменной

| Признак | corr с `median_house_value` |
|---|---|
| `median_income` | **0,688** |
| `total_rooms` | 0,134 |
| `housing_median_age` | 0,106 |
| `households` | 0,066 |
| `total_bedrooms` | 0,050 |
| `population` | −0,025 |
| `longitude` | −0,046 |
| `latitude` | −0,144 |

Топ-3 по |corr|: **`median_income`, `latitude`, `total_rooms`**. Матрица scatter показывает
явный восходящий тренд у `median_income`, тогда как `total_rooms` — слабая веерообразная связь
(это размер района, а не дома) — намёк на необходимость признака-отношения.

## 5. Ответы на итоговые вопросы

1. **Три проблемы качества.** (а) 207 пропусков `total_bedrooms` — заполнять только на train.
   (б) Целевая переменная цензурирована на 500 001 (а `median_income` / `housing_median_age`
   ограничены) — отбрасывать или моделировать явно. (в) Сильная правосторонняя асимметрия
   и разные масштабы у счётных признаков — логарифмирование + масштабирование; плюс
   `ocean_proximity` нужно закодировать.
2. **EDA только на train.** EDA определяет решения по моделированию (заполнение пропусков,
   обрезка, преобразования, выбор признаков), то есть извлекает параметры из данных. Делать это
   на всём датасете — утечка информации из теста в эти решения, и hold-out оценка перестаёт быть
   несмещённой.
3. **Идея признака.** `rooms_per_household = total_rooms / households` (затем `bedrooms_ratio`
   и `population_per_household`): сырой `total_rooms` измеряет размер района, а отношение —
   сам жилой объект, и коррелирует с ценой гораздо сильнее.
