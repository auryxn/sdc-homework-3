# SSE Task 18 — Gain Creators and Pain Relievers

**Subject:** Soft Engineering · **Course:** 2026 HR S5 Soft Engineering

## Task

Return to the list of user jobs from Task 16. Ask ChatGPT to identify the features of the
application that act as gain creators and the features that act as pain relievers.

## The system

The same **self-service book-loan kiosk** (city public library). The course prompt uses a
financial assistant application as an example; I replaced it with my chosen system so the
answer stays on the same user jobs as Tasks 16–17.

## Prompt used

> Let's look at the self-service book-loan kiosk application.
> 1. Define the features of the application that play the role of gain creators.
> 2. Define the features of the application that are pain relievers.

## ChatGPT result (for the assignment chat)

| Feature | Gain creator for | Pain reliever for |
|---|---|---|
| Self-service borrow and return in one flow | Speed; independence from the desk | Queue at the desk; limited opening hours |
| Due date shown on screen and printed on the receipt | Planning the reading; control | Forgotten due date; surprise fine |
| "What I hold" / loan history | Knowing what is at home; control | Uncertainty after a return |
| Availability status with "in sorting / last seen" | Confidence before the trip | Catalogue says "available", shelf is empty |
| Clear error screen with the next step and a "call staff" button | Confidence; less frustration | "Unknown item" dead end; queue behind |
| Return confirmation with date and time | Peace of mind | No proof that the return was registered |
| Privacy screen and auto-clear after the session | Privacy; comfort | Previous reader's history on screen |
| Remote diagnostics and status monitoring | Uptime for IT; fewer surprises | Outage discovered by readers |
| Accessible height, large buttons, multilingual UI | Ease for all readers | Physical strain; language barrier |
| Card/RFID plus manual number entry | Speed | Card does not read |

### Where the fit is strong, partial or absent

| Area | Fit | Why |
|---|---|---|
| Borrow/return flow, due date, loan history, privacy | **Strong** | These are the kiosk's own functions |
| Availability status, error recovery, accessibility | **Partial** | Depends on the catalogue, the branch and the UI |
| Shelf accuracy, remote monitoring | **Absent** | Needs the catalogue, shelving and IT monitoring, not only the kiosk |

## Short conclusion

The kiosk's strongest gain creators are speed and clarity; its strongest pain relievers are
confirmation and privacy. The weak spot is everything that happens outside the kiosk screen:
shelf accuracy, the state of the book, and the monitoring of the terminal.
