# SSE Task 17 — Gains and Pains

**Subject:** Soft Engineering · **Course:** 2026 HR S5 Soft Engineering

## Task

Return to the list of user jobs from Task 16 and, for each job, identify the gains the user
wants and the pains that irritate them before, during and after trying to do the job.

## The system

The same **self-service book-loan kiosk** (city public library) and the same reader jobs from
Task 16.

## Prompt used

> Return please to the list of user jobs. For each job detect:
> 1. Gains as results the user wants to get.
> 2. Pains that irritate the user before, during and after trying to do his jobs.

## ChatGPT result (for the assignment chat)

| Job | Gains | Pains before | Pains during | Pains after |
|---|---|---|---|---|
| Find the book in the catalogue and check the shelf | Know before leaving home that the book is there; save a trip | Catalogue says "available", but the shelf is empty; the status is not live | Searching the wrong shelf; asking a librarian | Wasted trip; the book is still not read |
| Walk to the shelf and bring the book to the kiosk | Get the book in hand today | The book may be misplaced; the branch is busy | Carrying a bag, stairs, narrow aisles | No pain if the book is found |
| Scan the card and the book | Borrow without the desk; keep the queue moving | Card left at home; card does not read | Scanner rejects the book; "unknown item" screen | Not sure the loan was registered |
| Understand the due date | Plan reading and return; avoid a fine | Due date is not visible before starting | Small screen; the date is easy to miss | Forget the date; get a reminder too late |
| Remember to return on time | Avoid a fine; keep the borrowing limit | No reminder; a busy week | The return trip competes with work | Fine; the reader blames the library |
| Check that the return was registered | Peace of mind; the loan is closed | No proof at the drop point | Kiosk error while returning | Fine for a book already returned |
| Feel confident that the machine is right | Trust in the system | A past error makes the reader suspicious | Unclear confirmation screen | Checking the account; calling the desk |
| Keep reading private | No one sees what I read | The screen is visible to the queue | The previous reader's history is still on screen | Worry that the history is stored |
| Not hold up the queue | Social comfort; finish quickly | A long queue behind | Fumbling with the card and the scanner | Embarrassment; avoid the kiosk next time |
| Ask a librarian for help when the kiosk fails | A human resolves the exception | The desk is closed or busy | Explaining the error; waiting | The issue is not resolved; the book is stuck |

## Short conclusion

The strongest gains are time and control; the strongest pains are uncertainty (shelf status,
return confirmation, due date) and the social pressure of the queue. The kiosk removes the
desk queue, but it creates new pains when its screen does not explain what happened.
